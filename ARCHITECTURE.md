# ARGUS architecture

`server.py` is a minimal executable entry point. `core/application.py` explicitly composes HTTP transport, preferences, projects, files/media, databases, plugins, logs and the persistent job queue; importing the entry point creates no application resources. SQLite owns project revisions, history, queue records and settings. The application supports one process and one data volume, not multiple replicas sharing the database.

`core/jobs.py` serializes tool and connection jobs independently of browser polling. `core/actors.py` validates inputs, combines installation configuration with permitted per-node parameters and persists results through `core/actor_results.py`. Installation-wide source switches/order and settings-only/secrets cannot be overridden by stale node params. Result nodes retain provenance and group context. Failures create a connected error node; partial results retain successful findings and an explicit warning/error output.

`core/graph.py` owns schemas and conflict merge semantics. Canonicalization and migrations are explicit. Verification is a user assessment rather than a guarantee inferred from tool success. Remote images are verified/cached through `core/media.py`; previews use same-origin file/media endpoints. Files are collected conservatively with reference checks and a grace period.

`core/access.py` keeps same-origin sessions and CSRF checks. The current interface automatically establishes sessions and has no user-login/token-entry dialog. This is not user management. `core/secrets.py` encrypts credentials and VPN preferences with an installation-local key that must accompany backups. Structured system logs are separate from editable research documents and project execution history.

ARGUS starts with no research plugins. Native plugins are listed in `plugins/native.json` and downloaded from the repository on install, checked against their SHA-256; their tools are installed into `DATA_DIR/tools` by the recipes in `core/tools.py`. Plugins, tools and community plugins run as unsandboxed child processes of the application. `core/jobs.py` runs a configurable number of tools in parallel, sharing one VPN lease. See [runtime](docs/worker-runtime.md).

The integrated VPN controller starts as a privileged child of the container supervisor before the unprivileged app. They share the container network namespace, verified over a private Unix socket. The controller owns tunnel processes, IPv4/IPv6 OUTPUT filtering, persisted enabled state and candidate health checks. The queue takes/releases a connection lease; rotation waits for active tools and subsequent jobs wait for a healthy tunnel. [VPN documentation](docs/vpn.md) describes the container permissions, exceptions, supported profiles and the live checks still required.

Frontend views are React components under `static/react/`; reusable controls (buttons, fields, selects, dialogs, pickers) live in `static/react/ui/`. Domain behaviour lives in state-only feature factories under `static/app/`, composed in `static/main.js`. Features never build or query application markup: they call the view commands listed in `viewCommands` (render, dialogs, navigation, status), which `static/react/controller.js` must supply. UI owns presentation, gestures and transient edits; the backend owns validation, persistence, research and execution. User-supplied JSON Transform JavaScript runs in a browser worker.

`npm run build` produces the checked-in production ESM bundle and source/hash manifest. Docker verifies the manifest without a Node runtime. Tests import the production feature factories or exercise the rendered bundle with fixture APIs. Styles live in `static/style.css` and `static/database.css`.

## Decisions and boundaries

- **HTTP:** the standard-library server fits the single-process deployment. `core/http_routes.py` is an ordered method/path table; request security checks run before dispatch, and endpoint handlers own body parsing. A framework migration would add dependencies without resolving the previous oversized dispatch methods.
- **Persistence:** parameterized SQLite transactions and optimistic revisions keep graph and database writes atomic. Dataset imports are immutable previews consumed in the same transaction as inserted records. A server database is appropriate if multi-user concurrent editing becomes a requirement.
- **Frontend:** React is the only active view renderer. `static/main.js` contains the shared domain composition used by the controller and production-bundle tests. The retired imperative renderers, dialogs and DOM helpers were removed. Domain geometry remains independent of React; the component library owns controls and interaction states.
- **Workflows:** actor execution has preparation, collection, failure recording and persistence phases. Result materialization separates unit preparation, placement, nodes and groups. Instagram and generic enrichment use per-run context objects, avoiding duplicated state passed through long argument lists. Contexts never survive between requests.
- **Errors:** expected application validation uses stable `DomainError`/`AppError` codes; `static/errors.json` holds their English text for the browser. Plugin, SDK, HTTP and job boundaries intentionally catch unexpected exceptions to preserve partial findings and keep background processing alive; low-level I/O errors propagate or are handled by specific types. These boundaries must not turn failed security setup into successful execution.
- **Language:** ARGUS is English-only. Interface text, plugin metadata, tool output and reports are written in English where they are produced; there is no translation layer. Plugins label their own parameters in `parameter_schema` (`label`, and `labels` for choices). Projects saved by earlier, German versions are converted once by the schema 2 migration in `core/migrations.py` (generated texts only; user-written text stays as typed).
- **Deployment:** the app and every plugin run as UID 10001. The supervisor needs only the capabilities for the integrated VPN and the privilege drop (see `deploy/README.md`).

See [runtime](docs/worker-runtime.md), [container permissions](deploy/README.md), [database imports](docs/databases.md) and [validation](docs/validation.md). Historical iteration notes live in `docs/archive/`; they are not current architecture specifications.
